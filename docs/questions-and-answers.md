# Q&A

## Q1. Kenapa hanya Monitors entity yang dikasih nama tablenya pada AppDbContext.cs, lalu apakah semuanya sudah otomatis dan tidak perlu di definisikan secara eksplisit? Karena terlihat kebanyakan cuma mengatur indexing saja.
**A:** Karena cuma monitors yang nama tablenya berbeda dari entity nya (`EndpointMonitor`), jadi ditulis eksplisit. Semuanya sebagian besar sudah otomatis seperti nama table diambil dari `DbSet` yang sudah menggunakan type dari entity nya dan juga `Id` yang sudah pasti dijadikan `primary key`

## Q2. Apakah struktur foldernya sudah best practice? Soalnya aku kebingungan di folder Monitoring sepertinya memuat banyak hal.
**A:** Wajar kalo untuk project sekecil ini. Struktur ini memakai pola folder per fitur: satu folder berisi semua yang berhubungan dengan satu fitur. Monitoring banyak file karena memang di situlah fitur utama aplikasinya, yaitu memantau endpoint.
